# XpanAce3Pro — 一加 Ace 3 Pro 哈苏 X-Pan 宽幅模式

给一加 Ace 3 Pro（PJX110）的相机开启哈苏 **X-Pan 65:24 宽幅模式** 的 KernelSU 模块，
配合 LSPosed 使用。**卸载即还原**，不改动系统分区。

> 作者：**Turbowfz**（Turbo）
> 模块本体：`XpanAce3Pro-v1.3.zip`（可直接刷入；**支持 Gitee 云更新**，管理器内可直接检查更新）

---

## 功能

- 开启相机 **X-Pan 65:24 宽幅模式**（哈苏实体皮肤 UI + 显影动画 + 胶片滤镜）
- **1× / 2× 统一 24.8MP 高像素出片（8192×3024，65:24）**（v1.3 起）
- **哈苏影调（自然影调 / 超光影引擎）已开**（v1.3 起，全局生效）
  照片 / 人像等普通模式出片会走影调链 —— 实测同场景对比：整体亮度 +15.5、
  对比度 −6.3、暗部占比 17%→7%（暗部大幅提亮、画面更通透）。
  ⚠️ **X-Pan 模式吃不到**（原因见"已知限制"，是硬件/APS 层限制，不是没做）。
  想关掉：`setprop debug.xpan.tone 0` 后重启相机。
- 拍出 65:24 宽幅照片，带哈苏水印
- **变焦条加了 28mm / 35mm 的等效倍率档**（v1.3 起）：显示为
  **1x / 1.2 / 1.5 / 2**（1.2 ≈ 28/24、1.5 ≈ 35/24），
  **每个档位都是真裁切**（视野真的变窄），文件统一 24.8MP。
  档位文字做了四舍五入（应用自带的格式化是截断，1.1667 会显示成 1.1）。
  实现方式：模块在拍照后按焦段对成片做中心裁剪、再放大回 8192×3024
  （原因见"已知限制"——本机 HAL 不会裁 X-Pan 的 65:24 拍照流）。
  说明：本机传感器在 HAL 里只有 12.5MP 的四合一读出，所以**真实细节上限就是 6.2MP**；
  变焦档裁完的真实细节 = 6.2MP ÷ 焦段²，放大回 24.8MP 是插值（文件大、细节不增）。
- 修复切换模式后的界面休眠、退出残留、快门锁死等一系列问题
- **卸载模块即完全还原**（hook APK 会自动卸载）

1. KernelSU 刷入 `XpanAce3Pro-v1.3.zip`
2. 之后有新版本时，**KernelSU 管理器内会直接提示更新**（模块走 Gitee 云更新通道，

## 卸载

在 KernelSU 中移除模块并重启。模块会自动清理 LSPosed 作用域与 hook APK，
`/odm/etc/camera/config/` 下三个相机配置由模块目录卸载自动还原。

## 原理

1. **配置对齐**：往 `/odm/etc/camera/config/` 放入对齐过的相机配置
   （`camera_unit_config`、`camera_unit_feature_config.protobuf`、`oplus_camera_config`），
   让系统认识 X-Pan 模式与 800T 胶片滤镜族
2. **尺寸修正 hook**（LSPosed）：X-Pan 申请的出流尺寸（1920x864 + 4096x1512）
   本机 HAL 不认，hook 改成实测能跑的组合 **预览 2304x1048 + 拍照 8192x3024**
   （默认档；`.xpan_smallpic` 存在时拍照流为 4096x1512）。
   v1.3 起变焦**不再**回退拍照流：既然 2× 构图与 1× 相同（见"已知限制"），
   两个焦段统一出 24.8MP 大图
3. **界面修复 hook**：X-Pan 的界面容器在部分进入路径下不会被应用驱动
   （内部状态停在 -1），hook 在超时后补一次初始化，让哈苏皮肤 / 显影动画 / 滤镜条正常出现
4. **变焦档位 + 真裁切 hook**（v1.3）：
   把变焦条那份 `List<Float>` 换成 24/28/35/48mm 的倍率（1 / 1.1667 / 1.4583 / 2），
   并把变焦条单位切成 mm（应用原生支持，只是默认显示 ×）；
   拍照后按焦段对成片做中心裁剪 + 放大回 8192×3024 写回（HAL 不会裁，见"已知限制"）

详细踩坑记录见源码内注释（`hook/src/com/xpanport/hook/XpanHook.java`）。

## 已知限制

- **HAL 不会裁 X-Pan 的 65:24 拍照流**，所以"真焦段"是模块自己裁的（v1.3 起）。
  证据链（2026-10-17，两次独立验证）：应用拍照请求里确实带了
  `android.control.zoomRatio=1.4583`，但同一个请求里还有固定的
  `com.oplus.opx.CropInfo=[0,780,4096,1512]`（65:24 带的裁剪指令），HAL 只认后者；
  拍照流宽度改成 4096 或 8192，出图构图都不变。
  试过并判死的替代方案：显式注入 `SCALER_CROP_REGION`（4:3 矩形）→ HAL serious error
  直接崩相机；注入 65:24 形状矩形 → 出图退回 4:3；改 `com.oplus.opx.CropInfo` → 同样
  退回 4:3。**结论：HAL 侧无解，只能在成片上软件裁。**
  模块的做法：拍照时记下焦段 → 新文件落盘后按中心 1/z 裁剪 → 放大回 8192×3024 写回。
  实测（静止目标模板匹配）：同构图假设 NCC **0.65**、真裁切假设 NCC **0.99**，裁切准确。
- **变焦上限 2.0×（48mm）**：这个模式在应用内部把变焦钳到 2.0
  （实测请求 2.5× / 3.54× 都被压回 2.0，钳制点在 `z1.m` 内部、比 `fh.g.f` 更早），
  所以**暂时没有 85mm 档**；要加得先挖出那处钳制。
- 变焦档（28/35/48mm）出片是 **JPEG（.jpg）**：重编码用的是 JPEG
  （HEIC 编码器是隐藏 API，应用进程里调不动），1× 仍是相机原生的 **HEIC**。
  另外变焦档的水印会被一起裁掉（水印在画面下缘），EXIF 也不保留。
- 出片尺寸固定 **8192×3024（24.8MP）**。想临时换 4096×1512（6.2MP）小文件档：
  新建 `/sdcard/DCIM/.xpan_smallpic` 空文件并重启相机（删掉文件即恢复）。
- **已修：相册里多出来的"0B 图片"**（v1.3 修订3）。原因：模块把原图 `.heic` 替换成
  `.jpg` 时，媒体库里那条 `.heic` 记录成了指向已删文件的僵尸记录 → 相册显示成空图。
  现在替换后会一并删掉那条记录；启动进 X-Pan 时还会自愈清理历史遗留的僵尸记录。
- **影调（BasicTone）为什么 X-Pan 吃不到**（2026-10-17 实锤，详见
  `12_验证/影调BasicTone-调研与实测结论.md`）：
  影调与滤镜是两条独立通道，影调的总闸门是 `com.oplus.natural.tone.support`，
  而**这个键在任何配置文件里都不存在**（一加13 也没有）→ 应用取默认 false。
  两条"改配置"的路都判死：① 写进 `oplus_camera_config` 无效（对照实验：同文件里
  另一个应用确实查询的键从 0 改成 1，应用照样读 false → 该文件不是这些开关的数据源）；
  ② 照抄一加13 的 APS 两条 tag（`aps.basictone.version` 等）→ 相机 native abort
  （`APSJsonParser::parseJsonFileParams` ← `camApsInitEnv`），本机 APS 不认识它们。
  所以模块改成在**应用侧接管**那个键（`CameraConfig.b` 是唯一查询口）→ 普通模式的
  影调链就通了。X-Pan 另有覆盖（`yh.c3.K1()` → `u6.o0.D()`，要求 master.mode.version
  正好 2.1/1.1，本机是 2.0）；实测只接管应用侧判定后 X-Pan 出片**毫无变化**
  （同场景各 2 张：亮度差 −0.54），而预览反而会变 → 会造成"预览与成片不一致"，
  因此 X-Pan 保持原样（所见即所得）。
- 0.6× 超广角在本机的成像通路未调通，已按稳定性移除
- 模式切换后边框 / 滤镜条可能**慢半拍**出现（等应用自己完成初始化，避免抢跑）
- 真实细节上限就是 6.2MP：传感器四合一读出 + HAL/APS 输出链决定；
  1× 的 24.8MP 是放大图，变焦档裁完的真实细节 = 6.2MP ÷ 焦段²，同样靠放大回大图
- 调试开关（改完重启相机生效）：`debug.xpan.tone=0` 关哈苏影调（回原厂行为）；
  `debug.xpan.swcrop=0` 关软件裁切；
  `debug.xpan.zooms=1,1.1667,1.4583,2` 自定义焦段倍率；`debug.xpan.split=1` 试"HAL 小流"（无效，留作复验）
