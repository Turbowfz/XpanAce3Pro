## 日志定位到的两个真正缺口

### 1. 相框条件补丁没有覆盖当前分支

第二张原调用记录：

```text
[XpanGainMapFrame] not exact XPAN frame overlay;
tagXpan=true infoXpan=true overlay=false
format/stage/geometry unknown; unchanged
```

已明确mode没串，但`main.v[4]`不是当前相框入口；没有把缺失数值猜成0或借最终照片ROI反推raw。原`q0.e`的AI判定与`q0.w`的v4门控是两层；type3/9及是否raw已经含框仍需实际字段，不能仅删除门槛就宣称修复。

### 2. APS直接编码绕过完整字节owner

第二张记录：

```text
[XdrBeforeSave] 7.013.51 c0 format=heic_8bits bytes=0
status=INVALID_INPUT ... null input
encoded owner unavailable before original update/save;
heifProcessInAps=true; unchanged
```

`CameraPicture.j0`真实来自`isHeifProcessInAps()`。该owner没有完整HEIC数组，原8×parser只能保留；APS持有detached输出FD，`c0`可以只是其后收尾，不能猜“编码一定发生在c0以后”。静态`c0/i0/j0/Q`也不产生新完整owner数组。

因此后续必须沿APS实际编码与增益参数接口补齐，或者取得最终完整buffer和关闭/独占契约。不能扫描旧图库、截断/重编码原HEIC、强改FD/HW、猜opaque gain-info偏移或用事后改图冒充native修复。
