# C16 / C17 支持基线与倍率验收

## 以用户实测为准

- **ColorOS16：独立Xpan模式可正常使用；ratioMax8×没有生效。**
- **ColorOS17：手机当前系统，需重新适配；不能删除C16适配。**
- v2.0/code20在同一独立模块保留两个分支。默认8192×3024、仅1×、水印隔离、8×只升不降目标保持。

## 支持矩阵

| 项目 | C16 | C17 |
|---|---|---|
| 精确相机版本 | 6.020.876 | 7.013.51 |
| SDK配套 | 本机C16 pinned unit/adapter | 本机C17 pinned unit/adapter |
| 配置和Hook | 保留C16原配置及精确成员 | 独立C17配置及成员，不混搭 |
| XPAN界面/滤镜/拍摄 | 用户确认原模块正常，后续改动仍需回归 | 当前实机模式、哈苏界面及拍摄已观察 |
| 8192×3024 | 保留既有默认 | 第一张新片照片ROI已像素核验 |
| ratioMax8× | **用户确认未生效** | **三张新片约4.95656×，未通过** |
| 相框增益 | 不据C17结果推断C16 | 内框174问题仍在，原生路径待修 |

同一版本按系统/app/SDK合同分别选择，不是把C16 SDK给C17 APK用。旧版效果声明与模拟日志不能覆盖用户实测。

## 回归原则

1. C16原已可用的菜单、哈苏界面、滤镜、显影与拍摄功能不删；未点名行为不改。
2. C17混淆成员和native调用只用于对应精确版本，不能把地址/结构套到C16。
3. 两代倍率都需要各自的新拍HEIC证据：tmap与关联XMP一致、目标8×、更高则保留、像素/Exif/尺寸/增益空间不被误改。
4. 没有对应系统的实机，标明仅本地回归，不能称两代倍率修复已验证。
5. 任何新插件hook或native payload要走可信接口与完整构建/签名/包装检验，不直接覆盖系统库或事后改原照片。

新增源码守卫明确检查C16分支仍存在；当前两代profile/配置/Java保存补丁40项专项回归通过，新增支持保留守卫9项通过。它们验证本地合同，不证明实际8×生效。
