# v2.0：原 C16 基线与一加 13 参考对照

## 适配对象不变

本版仍是独立 **XpanAce3Pro**，以原 C16 能用的 X-Pan 路线为基础，补当前 Ace 3 Pro / PJX110 的 C17，相机 `7.013.51`。版本统一 **v2.0 / code20**。保留默认 **8192×3024、仅 1×、XDR 上限至少 8×、哈苏界面／滤镜及水印隔离**。

一加 13 全量 OTA 和 OnePlusOSS 官方源码确实已使用，不是只凭缺符号判断能否移植。它们用来核对原生功能和格式，不直接替换 Ace 的 APK、SDK、传感器、HAL 或整套 native 库。

## 官方源码如何用于提取和兼容

Linux v6.1 EROFS 与本地 OnePlus 官方 6.6 源码对 12-bit compact mapping 的规则一致：普通 pcluster 从 base+1 计数，big pcluster 从 base+0 并按 CBLKCNT 增量计数。参考包的 LZ4 config 指定最大 4 个物理块，压缩 advise=7。

读取器已按该原格式验证头、CBLKCNT、精确块数、重叠与字节预算；不搜索邻块猜解压成功。原设备读取限制仍为 4 MiB，本地 OTA 才允许显式较大预算。

官方 camera-kernel／设备树继续用于了解 ISP 请求边界，但不能据此宣称用户空间 APS 算法任意尺寸都可用。

## 为什么没有直接移植一加 13 的 protobuf

两机 protobuf **描述符 SHA-256 完全相同**：

`a3d0cf64b076d0a39c05215c9c6951609f2996c9d05b244d3353c3e78d0c1ceb`

但索引池和消费者不同。donor XPAN 的 `common` 表只有以下 8 条：

| 功能 | 键／默认值 |
|---|---|
| focus_exposure | 本身功能键／空 |
| xpan | `com.oplus.camera.feature.xpan`／空 |
| assist_view | 本身功能键／空 |
| assist_view | `pref_assist_gradienter`／off |
| face_detect | 本身功能键／on |
| zoom | 本身功能键／空 |
| filter | `feature_filter_index`／0 |
| beauty | 本身功能键／off |

`com.oplus.camera.feature.xpan` 在 Ace 原索引池里不存在。更重要的是：应用配置有 `common` 回退合并，原生 producer 功能表却选择精确摄像头映射。直接换成 donor 的 `common` 八项可能丢失 Ace `rear_main` 原生参数。

因此：

- 保留与原 C16 发布包逐字节一致的本机 unit/PB 基线及 `rear_main` 路线。
- 只在 XPAN 的应用功能生成范围加入哈苏 UI feature，非 XPAN 工厂请求在构造前阻止。
- 不把 donor 索引或 APS 算法整体移植，不因功能数量少就假定它是本机最小可用表。

## 本轮真正补的功能点

1. **C17 菜单入口**：原有数据库不必因为配置改变自动新增模式。补丁跟随原正常读取，在原连接上只读核对快照，给列表副本追加原厂 XPAN 项；点击 id28 经原静态映射进入 `xpan`。不删库、不升级 schema、不改变已有模式排序。
2. **临时 XPAN 菜单编辑标记**：原程序编辑是 UPDATE-only，未入库虚拟项不能保存跨位置排序。因此新临时项的数据对象使用不可编辑标记，已有入库 XPAN 的原属性不变。但后续 UI 是否完整传递该标记尚待实机核对，不能把字段设置当作拖拽保护已验收。
3. **C17 原生界面时序**：`dl.w.h` 先排异步任务，真正原生创建在 `uq.l.b7`。不能看到初始状态 -1 就照搬 C16 强唤醒。已补精确旧异步任务的代次保护，避免进出模式复用同一个 view manager 时旧任务重复建面板。对照 donor `el.v / vq.m / cl.d`，其原生创建和实体滤镜绑定结构与 Ace `dl.w / uq.l / bl.d` 相同，未确认需要搬 donor 资源／类才能补齐的缺口；没有据此宣称画面已渲染。
4. **C16 原生滤镜兼容**：原 IPU 哈苏滤镜直接读取 SDK 配置，不经过应用的六个 getter。已在 XPAN 组构建范围补齐样式 gate 和版本 3，保持原始加密 vendor 不变，且不执行共享 Coui 缓存写入；普通滤镜行为不因此改变。专用本地回归通过，不等于原 C16 手机渲染已复测。
5. **APK 配套引导**：首次主动打开可看到安装／LSPosed 相机作用域步骤和精确版本提示；它是本应用指南，不伪装官方激活弹窗，不擅自改 LSPosed 数据库或作用域。

## 仍须严格区分的实效边界

- 当前手机有效路径里的 SDK 仍是 C16 内容，C17 的取消拍摄接口与它有真实语义差异；不能简单放宽哈希或把取消转为拍照。测试前恢复原厂加载环境是设备操作，尚未执行。
- 新建菜单副本、UI 任务 guard 注册、编译通过，不等于实机界面／拍照通过。
- XDR 仍只处理完整 HEIC 内存副本。HardwareBuffer／原生后建 gainmap-info 布局与严格新 capture→保存身份关联尚未全部证实，不猜偏移、不截断落盘照片。
- 签名必须沿用原发布证书。当前正确证书的 keystore 凭据关联尚未提供，不新建 key，不用旧测试证书顶替。
